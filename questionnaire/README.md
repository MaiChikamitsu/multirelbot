# 第三者評定の現在の画面

現在の流れは **招待コード → 回答者IDを本人が入力 → テーマ選択 → 説明 → 動画評定** です。役割A/B/Cは入力・表示しません。IDは自動発行ではなく数字の入力式です。同じコードに紐付けたIDを後から別IDへ変更することはできません。

6テーマを表示し、未登録のテーマは「このテーマの動画はまだありません」と表示します。動画を公開する実験設定には `observer_enabled: true` を付けます。複数組を登録したテーマでは会話の選択も表示します。

無人島の説明には15分間の議論のテーマ・ディベートから3人の案を1つにする経緯・会話の始まりから現在までを踏まえた親密度評定・尺度の例を記載しています。操作説明も回答前と回答中に確認できます。

## 第三者用の招待コード

```sh
python3 -m questionnaire invite-observer
```

1人に1コードを渡してください。初回に本人がIDを入力し、同じコードで再ログインするとそのIDとテーマごとの保存状態を再利用できます。別コードから同じIDを登録することは拒否します。確認用は `--preview` を付けます。既存の確認コードは同じ値で使えます。

```sh
python3 -m questionnaire invite-observer --preview
python3 -m questionnaire revoke-observer --id 900001
```

## 振り返り再生

- 通常再生は現在の区間の先頭から終わりまでです。
- 「この区間を最初から再生」で通常の区間再生に戻れます。
- 「動画を任意の場所から見る」で、会話開始時刻から現在の区間の終了時刻までシークできます。まだ先の区間にシークしようとすると現在の区間の終了位置に戻して停止します。
- 設問を保存して次へ進むと通常の区間再生へ戻ります。
- この制御はブラウザの操作補助であり、意図的な開発者ツール操作等による全動画へのアクセスや全区間の完全視聴を保証する仕組みではありません。

## 第三者の回答は別出力

```sh
python3 -m questionnaire export-observers --output questionnaire/private/exports/observer_ratings.csv
```

完了した第三者評定だけを出力し、確認用は除外します。元フォームと同じ順序の列で「割り当て」は空欄、最後に「実験ID」列を付け、同じ回答者が複数会話を評定した場合も識別できます。旧来のA/B/C本人の回答とは別テーブル・別コマンドです。元の回答は削除・書換えません。役割なし・任意人数の第三者評定は、現在の「3人のA/B/C当事者」を前提とする分析設定に自動混入させません。

```sh
python3 -m unittest questionnaire.test_observers questionnaire.test_questionnaire -v
```

以下のA/B/Cへの招待・本人評定の説明は、既存データを扱うための旧方式です。新しい第三者評定には上記のコマンドを使ってください。

# 動画＋回答画面（questionnaire）

既存の推定viewer・分析レポートとは独立した回答用アプリです。Flask＋SQLiteで動作し、推定APIやAzure設定を読み込みません。実際の動画・区切り時刻・公開先はまだ登録していません。

## 動画はどこへ置くか

**`questionnaire/private/videos/` に置いてください。** ブラウザ再生用のMP4（H.264映像＋AAC音声推奨）またはWebMを使用します。ファイルを置くだけでは公開されず、招待コードでログインした参加者の割当て動画だけを `/media` 経由で配信します。private以下はGit管理対象外です。

動画を41本に切る必要はありません。動画1本を、登録した開始・終了秒数で区間再生し、3発話ごとに停止します。

## 既存フォームと同じ項目

参照したファイルは「【修正版】（直後）予備実験アンケート （回答） (1).xlsx」の「フォームの回答 2」です。

- タイムスタンプ：全回答完了時刻をサーバーで記録（CSVは日本時間）。区間ごとの保存時刻もDBに保持。
- ID・割り当て・テーマ：招待コードに紐付けた値を表示・保存。参加者による誤選択を防ぐため編集不可。
- 1〜54番の「AとB」「BとC」「CとA」：−1.0〜＋1.0を0.1刻みで入力。初期値は空欄で、0も明示入力。今回の動画が41区間なら41番まで表示し、42〜54はCSVで空欄。
- 最後に「感想」（任意）。

テーマの選択肢は、無人島／AI／外国人受け入れの各「ー縛りあり」「ー縛りなし」の6つです。元のExcelに評価尺度の詳しい説明文は含まれていません。追加の教示がある場合は、それを確定して画面へ反映してから本実験に使用してください。フォームの回答1は使用しません。

## 手元での起動

以下はすべてmultirelbotのルートで実行します。

```sh
python3 -m pip install -r questionnaire/requirements.txt
python3 -m questionnaire serve
```

ブラウザで `http://127.0.0.1:8892/` を開きます。既存の8889の推定viewer・8890の分析レポートとは別ポートです。これは開発・手元確認用で、インターネットへ直接公開しません。

## ほかのパソコンから回答する（GPU不要）

サーバーは特別な機械の名前ではなく、画面・動画を配信して回答を受け取る役割です。このアプリはGPUを使いません。推定用のLLMも呼びません。

同じ実験室・同じネットワークで使う場合は、あなたのPCで次のように起動できます。

```sh
python3 -m questionnaire serve --host 0.0.0.0 --port 8892
```

別のPCで `http://あなたのPCのLAN内IP:8892/` を開きます。127.0.0.1はアクセスするPC自身を指すため、他のPCへ渡すURLには使いません。あなたのPCを起動し、アプリを終了させず、スリープしない状態に保ちます。Wi-Fiの端末間通信制限やPCのファイアウォールによっては接続できません。大学・実験室で許可された信頼できるネットワークの手元テストに使用し、同じWi-Fiにいる人全員へ招待コードを渡さないでください。

このコマンドをルーターのポート開放等でインターネットへ直接公開しないでください。自宅など別のネットワークから使う場合は、下記のHTTPS公開構成を使用します。クラウドの一般的なCPUサーバーでよく、GPUサーバーや専用ハードウェアの購入は不要です。

## 実験を登録する

### 1. 動画と会話テキストを対応させる

たとえば `questionnaire/private/videos/muzintou_ari.mp4` を置いた場合：

```sh
python3 -m questionnaire prepare --id muzintou_ari --video muzintou_ari.mp4 --conversation estimation_accuracy/conversation_muzintou_ari.txt --theme 無人島ー縛りあり
```

次のテンプレートを生成します。既存ファイルは上書きしません。

```
questionnaire/private/configs/muzintou_ari.json
questionnaire/private/configs/muzintou_ari_boundaries.csv
```

会話は既存viewerと同じ「[A] 発言」「[B] 発言」「[C] 発言」形式を読み、ロボットを除く3発話ごとに区切り候補を作ります。2組目も `--id muzintou_ari_2` と別動画・別テキストで同様です。

### 2. 区切り時刻を入力する

boundaries.csvの **end_seconds列**に、3・6・9…発話目の終了時刻を「動画先頭からの秒数」で入力します。`12.35`のような小数が使えます。最後の話者と発言もCSVに入るため照合できます。**等間隔・音声の無音区間・推測だけで自動確定はしません。** 実験用テキストと動画の分割を合わせて確認してください。

冒頭に説明や待機時間があれば、設定JSONのstart_secondsを変更します。末尾に3発話未満の余りがある場合、その余りは評定対象外です。時刻付き書き起こしがあれば作業を減らせますが、現在のtxtだけでは境界の秒数は分かりません。

登録します。

```sh
python3 -m questionnaire register --config questionnaire/private/configs/muzintou_ari.json --boundaries questionnaire/private/configs/muzintou_ari_boundaries.csv
```

回答開始後に区切りや動画設定を変更することは拒否します。修正が必要なら別の実験IDを使用してください。

### 3. 招待コードを発行する

実際の回答者ID・役割を指定します。IDは数字で、全実験を通して再利用しません。下のIDは例です。

```sh
python3 -m questionnaire invite --experiment muzintou_ari --id 7 --role A
python3 -m questionnaire invite --experiment muzintou_ari --id 8 --role B
python3 -m questionnaire invite --experiment muzintou_ari --id 9 --role C
```

各コードはその参加者だけに渡してください。コードはDBにハッシュで保存し、元の値は再表示できません。コードをURLのクエリには付けず、画面へ入力します。以下で失効・再発行できます。

```sh
python3 -m questionnaire revoke --id 7
python3 -m questionnaire rotate-code --id 7
```

失効・再発行時は既存のログインも無効になります。回答データは残ります。

## 参加者の流れ

1. 招待コードを入力。ID・役割・テーマを確認。
2. 動画の今回の区間を再生。境界で自動停止。
3. 3ペアの値を入力し「回答を保存して次へ」。区間ごとに即時保存。
4. 最後に感想を入力し、完了。

同じコードでログインし直すと続きから再開します。重複送信や複数タブからの競合では次の回答を上書きせずエラーにします。すでに保存した区間への回答変更機能はありません。回答の再編集を許す場合は、その方針を先に決めて別途実装してください。

自動停止・回答ボタンの制御は回答を補助するものです。視線や完全視聴を証明したり、開発者ツールによるシークやAPI直接操作を完全に防止したりする仕組みではありません。

## 回答を取り出して既存の分析へ

```sh
python3 -m questionnaire export --output questionnaire/private/exports/form2.csv
```

元のフォームの回答2と**同じ167列・同じ見出し順**のCSVを出します。全区間の回答と最後の完了操作が済んだ参加者だけを出力します。途中回答はDBに残りますが、完了回答としては出しません。`--experiment muzintou_ari`で実験を限定できます。CSVの各点の値は丸めません。感想が数式として実行されないよう、先頭が数式記号の自由記述には安全な接頭辞を付けます。

既存のanalyze_relations.pyも、Excelに加えてこのCSVを読めるように拡張しています。分析設定のsurveyを次のように変更できます。

```json
"survey": "questionnaire/private/exports/form2.csv"
```

同じテーマが複数組あっても、respondent_ids・roles・episode・aggregate_runで対応させます。既存のExcelを上書きしたり、既存の評定と自動で混ぜたりはしません。同じ3人に旧フォームと新画面を両方回答してもらう場合は、どの回答を評価に使うかを明示して別の分析設定で比較してください。

## インターネット公開

**現在は未公開です。** このディレクトリには公開に必要なアプリ・設定例を用意しています。公開先サーバー、HTTPSのドメイン、永続保存領域を確保してから使用します。Sites等の静的ホスティングへこのディレクトリをそのままアップロードする方式ではありません。

1. 公開サーバーへ、このquestionnaireパッケージと依存関係を配置する。
2. private以下をWebルート外に置き、サービス実行ユーザーだけが読み書きできる権限にする。DB・動画・秘密鍵・回答をGitへ入れない。
3. env.exampleを参考に、本物の公開URLとランダムな秘密鍵を環境変数へ設定する。環境変数は自動ロードされない。見本の値は使わない。
4. Gunicornは127.0.0.1にだけバインドし、Caddy等のHTTPSリバースプロキシを1段だけ前に置く。ProxyFixはその構成専用。

リポジトリルートからの起動例：

```sh
gunicorn --bind 127.0.0.1:8892 --workers 2 --timeout 120 questionnaire.wsgi:app
```

`QUESTIONNAIRE_PUBLIC=1`時は、HTTPSのBASE_URL・十分な長さの秘密鍵がなければ起動を拒否します。ブラウザからのHTTPSアクセスとHostも検査します。TLSはリバースプロキシが終端し、Gunicornをインターネットから直接接続できないようにしてください。

参加者の招待コードは割り当てた動画への閲覧権限でもあります。渡す相手・方法を管理してください。コード共有や画面録画・動画の保存を完全に防ぐ機能ではありません。研究用動画を保存する場所・期間・アクセス担当者は、実験の運用として確定してください。

- 動画はログイン必須、回答者には割り当てた動画のみ。
- 他人の回答閲覧・公開の管理画面・公開CSVダウンロードはなし。管理はサーバーの端末からのみ。
- セッションCookieはHttpOnly/SameSite、公開時Secure。POSTはCSRFトークン必須。
- 招待コード試行はIPごとに回数制限。コンテンツ型検査・CSP・フレーム埋込み禁止・no-storeヘッダー付き。
- 動画のHTTP Rangeに対応。大容量動画は帯域と同時接続数を事前に確認。
- SQLiteの永続ディスクを使用。データと秘密鍵を管理者限定でバックアップする。秘密鍵を紛失・変更するとログインは失効するが、招待コードで再ログインできる。

このテストで認証・分離・保存を確認していますが、インターネット公開後の安全性や運用を無条件に保証するものではありません。公開先の設定・通信・実動画再生・3人同時利用を本番前に確認してください。

## 文字版アンケート

動画版は `/`、文字版は `/text` から回答します。同じ招待コード・回答者IDを使えますが、選択状態と回答は別の実験IDで保持します。無人島の文字版は `muzintou_ari_text`、動画版は `muzintou_ari` です。第三者CSVの実験ID列で区別できます。

文字版設定は `private/configs/muzintou_ari_text.json` に保存しています。`modality: "text"` と `turns`（speakerとtext）を指定し、3発話を1区間とします。現在の区間と直前2区間を表示し、それ以前は折りたたみます。まだ先の区間の文章はAPIでも返しません。前の評価の確認・修正も動画版と同じ操作です。

## 自動停止だけのプレーヤー

```sh
python3 -m questionnaire.player
```

このMacで http://127.0.0.1:8893/ を開きます。登録済みの動画と停止時刻をそのまま使用します。招待コード・回答入力は不要で、アンケートの回答データは変更しません。停止後は「次の区間を再生」で続けます。最後の区間で終了します。「この区間を最初から」「最初から」で再視聴できます。このプレーヤーはローカル利用用です。
